# Планировщик ухода за кожей

Консольная программа, которая каждый день составляет план ухода за кожей на утро и вечер по правилам моих средств и истории их применения.

## Какую рутину автоматизирует

У меня несколько активных средств (сыворотка с ретинолом, пэды с витамином С, энзимная пудра, микротоковое устройство Medicube), которые нельзя использовать каждый день и нельзя сочетать между собой. Раньше я каждый день вспоминала, когда последний раз был ретинол, можно ли сегодня Medicube и что с чем нельзя, и легко сбивалась, особенно после пропусков. На это уходило 5-10 минут в день.

Теперь программа сама решает, что можно сегодня, и показывает готовый список шагов.

## Как запустить

Нужен Python 3. Внешние библиотеки не нужны.

```
python main.py
```

В меню: `1` — план на утро, `2` — план на вечер, `3` — выход. После плана программа спрашивает «Сделала?». Ответ «да» записывает применённые средства в историю.

## Файлы

- `main.py` — меню: показ плана и отметка выполнения.
- `rules.py` — правила: интервалы, конфликты, сборка плана, «сэндвич» с ретинолом.
- `storage.py` — чтение и запись JSON-файлов.
- `products.json` — мои средства и их правила.
- `history.json` — история применений. Это личные данные, поэтому файл не хранится в репозитории (указан в `.gitignore`). Программа создаёт его сама при первой отметке «да».

## Правила (поля в products.json)

- `time` — утро, вечер или оба.
- `order` — порядок нанесения.
- `interval_days` — раз во сколько дней можно (`null` — каждый день). Например, ретинол — раз в 3 дня, Medicube — раз в 2 дня.
- `incompatible` — с чем нельзя в один приём.
- `priority` — важность: при конфликте остаётся средство с большим приоритетом.
- `in_use` — пользуюсь ли сейчас.
- `standalone` — ставить ли средство в план отдельно (крем Uriage используется только вместе с ретинолом).
- `sandwich` — у ретинола: нанести крем, подождать, нанести ретинол, снова крем.

## Как программа составляет план

1. Отбирает средства, которыми я пользуюсь, подходящие по времени суток.
2. По истории находит дату последнего применения и проверяет, прошёл ли интервал.
3. Сортирует средства по приоритету и берёт по одному. Если новое средство несовместимо с уже взятым, оно откладывается.
4. Сортирует план по порядку нанесения и разворачивает ретинол в «сэндвич».

## Краевые случаи

- **Пропущенное применение.** Отдельного кода для переноса нет: если ретинол пропущен, интервал с последнего применения всё равно прошёл, и на следующий день ретинол снова попадает в план.
- **Конфликт средств в один вечер.** 20 октября совпали Medicube и энзимная пудра — остался Medicube (приоритет 3 против 2). 22 октября совпали ретинол, Medicube, пудра и крем Celimax — остался ретинол (приоритет 5), остальные показаны в строке «Не сегодня» с причиной.
- **Отложенное из-за конфликта средство** не теряется: оно попадает в план в ближайший день, когда нет конфликта.
- **Несовместимость указана только у одного средства.** Совместимость проверяется в обе стороны, поэтому такая ошибка в данных не приведёт к опасному сочетанию.
- **Средство ни разу не использовалось** (пэды с витамином С): истории нет — средство можно сразу.
- **Средство временно не используется** (крем-бустер с ретиналем): `in_use: false`, программа его пропускает. Чтобы начать им пользоваться, достаточно поменять одно поле.
- **Повторное открытие плана после отметки «да».** Если средство уже применено сегодня, оно остаётся в сегодняшнем плане, и план не меняется посреди вечера.
- **Повторная отметка «да» в тот же день.** Одинаковые записи в историю не дублируются.
- **Крем для «сэндвича» не найден по id.** Ретинол показывается без сэндвича, программа не падает.
- **Нет файла истории или он пустой** — история начинается заново.
- **Нет файла со средствами или он пустой** — понятное сообщение, и программа завершается.
- **Неверный ввод в меню** (`abc`, `5`, пустая строка) — программа просит ввести 1, 2 или 3. Ответ «Да», «ДА» или « да » с пробелами тоже распознаётся.

## Известные ограничения

- Синтаксическая ошибка внутри JSON (например, пропущенная запятая) не обрабатывается: для этого нужна конструкция `try/except`.
- Дата в истории должна быть строго в формате `ГГГГ-ММ-ДД`.
- Сегодняшняя дата берётся с часов компьютера.
